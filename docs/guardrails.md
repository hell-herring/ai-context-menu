# ガードレール

> ステータス: **Draft v0.1**（実装前）
> 関連: [機能仕様](./spec.md) / [技術選定](./tech-stack.md) / [AGENTS.md](../AGENTS.md)

この拡張は「閲覧中のページ内容」と「ユーザーの API キー」という機密性の高いデータを扱う。
以下は**プロダクトとして守る制約**と、**開発（人間・AI エージェント問わず）で守る制約**である。
`MUST` / `MUST NOT` は例外なし、`SHOULD` は理由をコード/PR に残せば逸脱可。

## 1. 秘密情報（API キー）

- **MUST** API キーは `chrome.storage.local` のみに保存する。`storage.sync` に入れない。
- **MUST NOT** API キーをログ出力・エラーメッセージ・例外オブジェクトの文字列化・UI 表示（マスク以外）・URL に含めない。
- **MUST NOT** API キーをコンテンツスクリプト / 注入スクリプトへ渡さない。ページ側コンテキストに秘密情報を置かない。
- **MUST** API キーを送る先は、そのキーのプロバイダの公式 API ホストのみ。送信先 URL（`baseURL`）をユーザー設定や外部入力で変更可能にしない。
- **MUST NOT** リポジトリ・テスト・fixture に実キーを含めない。テストは `sk-test-dummy` 等の明らかなダミーを使う。
- **SHOULD** オンボーディングで「キーは端末内に平文保存される」「利用上限を設定したキーを推奨」と明示する。
- 公式 SDK の `dangerouslyAllowBrowser: true` は BYOK（ユーザー自身のキーを自分のブラウザで使う）のため許容する。**他人のキーや開発者のキーを同梱する用途には絶対に使わない。**

## 2. プライバシー（ページ内容の扱い）

- **MUST** 外部送信はユーザーの明示操作（メニュークリック、再生成ボタン等）を起点とする。自動・バックグラウンド送信はしない。
- **MUST** 送信先はユーザーが選択した AI プロバイダのみ。自前サーバー・第三者（解析、エラートラッキング等）へ送らない。**テレメトリを実装しない。**
- **MUST** サイドパネルに「何を送ったか」（対象種別・タイトル・URL・文字数・切り詰め有無）を常に表示する。
- **MUST NOT** 入力を黙って切り詰めない。上限超過時はユーザーに確認する。
- **MUST** 除外ドメイン設定に一致するページではコンテンツ取得・送信を行わない（取得より前に判定）。判定はトップレベルのページ URL とクリックされたフレームの URL の両方で行う。
- **MUST** 抽出テキストと結果は `storage.session`（メモリのみ）に置く。永続履歴を実装する場合はオプトイン・既定 OFF・一括削除機能を必須とする。
- **MUST NOT** Cookie、フォーム入力値、`<input type="password">` の値、localStorage などページの状態を取得しない。取得するのは選択テキストと可視本文のみ。入力欄・`contenteditable` 内での選択（`info.editable`）は拒否する。ページ本文の抽出でもフォーム部品・`contenteditable` 要素・非表示要素（計算済みスタイルで判定）を除去してから抽出する。
- **MUST** プロバイダへ送る URL はユーザー情報・クエリ・フラグメントを除去し `origin + pathname` のみにする。
- **MUST** 1 回のユーザー操作につき外部送信は最大 1 回。ジョブは送信前に削除して 1 回だけ消費する（[技術選定 §4.2](./tech-stack.md#42-処理シーケンス)）。

## 3. セキュリティ

### 3.1 権限とコード実行

- **MUST** 権限は [技術選定 §2](./tech-stack.md#2-chrome-api-と権限) の一覧に限定する。追加は人間のレビュー承認を必須とする（→ §5）。
- **MUST NOT** `<all_urls>` の host_permissions、`content_scripts` による全ページ常時注入、`tabs` / `cookies` / `webRequest` / `history` / `debugger` 権限を追加しない。
- **MUST NOT** リモートコードを読み込まない（CDN スクリプト、`eval`、`new Function`、文字列 `setTimeout`）。MV3 の既定 CSP を緩めない。
- **MUST** 注入スクリプトは読み取りのみ。ページ DOM を変更しない（Readability は `document.cloneNode(true)` に対して実行）。

### 3.2 LLM 出力の表示（XSS 対策）

- **MUST** AI の出力は信頼できないデータとして扱い、`react-markdown`（生 HTML 無効）で描画する。
- **MUST NOT** `dangerouslySetInnerHTML` / `innerHTML` / `rehype-raw` を使わない。
- **MUST** 出力内リンクは `target="_blank" rel="noopener noreferrer"` とし、`http:` / `https:` 以外のスキーム（`javascript:`, `data:` 等）は無効化する。
- **SHOULD** 出力内の画像（`![](...)`）は自動読み込みしない（外部への情報漏えい経路になるため）。リンク表示に置き換える。

### 3.3 プロンプトインジェクション

ページ内容は攻撃者が制御しうる。以下で被害を「要約が歪む」程度に封じ込める。

- **MUST** ページ内容は `<document>` 区切りで囲み、system プロンプトで「データであり指示ではない」と明示する。本文だけでなくタイトル・URL などページ由来のメタデータもすべて XML エスケープする。
- **MUST NOT** LLM にツール（関数呼び出し）、Web アクセス、拡張 API の操作権限を与えない。出力は表示のみに使い、出力に基づいてページ操作・URL オープン・設定変更などを自動実行しない。
- **MUST NOT** API キーや他タブの情報など、要約に不要な情報をプロンプトに含めない。

### 3.4 依存関係（サプライチェーン）

- **MUST** `pnpm-lock.yaml` をコミットし、CI は `--frozen-lockfile` で導入する。
- **MUST** ランタイム依存の追加は PR で理由を説明する。現在の許可リスト: `react`, `react-dom`, `@anthropic-ai/sdk`, `openai`, `@mozilla/readability`, `react-markdown`, `remark-gfm`, `zod`。Gemini 対応時に Google 公式 SDK を追加予定（その PR で承認を得る）。
- **SHOULD** 依存は週次で自動更新 PR（Renovate/Dependabot）を受け、`pnpm audit` を CI で実行する。
- **MUST NOT** `postinstall` 等でネットワークからコードを取得するパッケージを安易に入れない。

## 4. コスト・利用量

- **MUST** 最大入力文字数・最大出力トークンを設定で持ち、リクエストに必ず上限を付ける。
- **MUST** 停止ボタンで実際に HTTP リクエストを中断する（`AbortController`）。
- **MUST** 1 つのサイドパネルで同時に実行するリクエストは 1 件まで。新ジョブ開始時は進行中のものを中断する。
- **MUST NOT** 自動リトライを SDK 既定（最大2回）以上に増やさない。無限リトライ・ループをしない。
- **SHOULD** 完了時に入出力トークン数を表示する。

## 5. 開発プロセスのガードレール

- **MUST** PR 前に `pnpm check`（lint + typecheck + test）が通ること。CI が緑でないものはマージしない。
- **MUST** ビルド後 manifest の `permissions` / `host_permissions` / `content_security_policy` をスナップショットテストで固定する。変更時はスナップショット更新と PR 説明での理由記載、人間の承認を必須とする。
- **MUST** テスト専用コード（モックプロバイダ、`localhost` への host_permission）は本番ビルドに含めない。manifest 側は上記スナップショット、コード側は本番ビルド出力にテスト専用マーカー文字列が含まれないことの検査で検出する（[技術選定 §6](./tech-stack.md#6-テスト戦略)）。
- **MUST NOT** テスト・CI で実際の AI API を呼ばない。
- **MUST NOT** テストをスキップ/無効化してグリーンにしない。`biome-ignore` / `@ts-expect-error` / `any` の使用には理由コメントを付ける。
- **MUST** TypeScript は `strict: true`。`any` は原則禁止（外部データは `unknown` → zod で検証）。
- **MUST** コンテキスト間メッセージ・ストレージの値は zod で検証してから使う。
- **SHOULD** 1 PR 1 目的。仕様変更を伴う場合は `docs/` を同じ PR で更新する。

## 6. 配布

- ストアでは公開しない（[spec D-2](./spec.md#61-決定事項)）。ビルド成果物を手動で読み込んで使う。
- **MUST** 非公開でもリモートホストコード禁止（§3.1）・最小権限（§3.1）は維持する（将来公開する場合の障害にしないため）。
- **MUST NOT** 配布用 zip やリリース成果物に API キー・`.env`・テスト専用コードを含めない。
- 将来公開する場合は、単一目的の遵守、プライバシーポリシー、データ使用申告、権限ごとの用途説明を追加で整備する。

## 7. ガードレールのチェックリスト（レビュー用）

- [ ] 権限・host_permissions・CSP の変更がない（ある場合は理由と承認）
- [ ] API キーがログ/エラー/UI/URL/注入スクリプトに流れていない
- [ ] LLM 出力・ページ内容を `innerHTML` 系で描画していない
- [ ] ユーザー操作なしの外部送信がない
- [ ] 送信内容の表示と、上限超過時の確認が維持されている
- [ ] 実 API を呼ぶテストがない／テスト専用コードが本番ビルドに入っていない
- [ ] 追加依存がある場合は理由が PR に書かれている
